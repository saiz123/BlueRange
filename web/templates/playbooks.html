SOC Playbooks

Reference these during investigations. Open mid-investigation for guidance.

Phishing Email Analysis

  1. Header analysis — Check From, Return-Path, Reply-To for discrepancies. Validate SPF/DKIM/DMARC.
  2. Sender domain — Check domain age (WHOIS), look-alike detection (typosquatting).
  3. URLs — Defang and check against threat intel. Look for credential-harvest page patterns (/login, /verify, redirect chains).
  4. Attachments — Hash the file, check against intel. Identify file type by magic bytes, not extension.
  5. Recipient context — Was this targeted? Did the user click? Check proxy/auth logs for follow-on activity.
  6. Verdict criteria — TP if SPF/DKIM fails AND suspicious URL/attachment. FP if all headers valid and no payload.
  7. Response — Block sender domain/IP, quarantine email, notify user, check for other recipients.
MITRE: T1566.001 (Spearphishing Attachment), T1566.002 (Spearphishing Link), T1078 (Valid Accounts)
🔐

Brute Force / Password Spray

  1. Identify pattern — Brute force: many attempts for one account. Spray: few attempts across many accounts.
  2. Source analysis — Single IP vs. distributed? Check ASN, geolocation, VPN/Tor exit nodes.
  3. Success indicator — Did any login succeed? Check for successful auth event (4624) after failures (4625).
  4. Lateral movement check — If success: check for new logins, file access, network connections from the compromised account.
  5. Verdict — TP if pattern present. Escalate if successful login detected or lateral movement found.
  6. Response — Block source IP, lock affected accounts, force password reset, alert account owners.
MITRE: T1110 (Brute Force), T1110.003 (Password Spraying), T1078 (Valid Accounts)
📡

C2 Beaconing Detection

  1. Beacon pattern — Regular interval connections to same destination (every N seconds/minutes). Check jitter.
  2. Destination reputation — Look up IP/domain in threat intel. Check if newly registered or on blocklist.
  3. Protocol — HTTP/S beacons: look for small fixed-size POSTs. DNS beacons: high-entropy subdomains. Check for unusual user-agents.
  4. Process context — Which process is making the connection? Parent process anomaly? (browser spawned by Office/script)
  5. Data volume — Small outbound data is C2 check-in; large outbound may indicate exfiltration stage.
  6. Verdict — TP if regular beaconing to unknown/bad IP + process anomaly. Escalate to L2 immediately.
  7. Response — Isolate endpoint, block destination, preserve memory/logs for forensics, escalate.
MITRE: T1071.001 (Web Protocols), T1071.004 (DNS), T1095 (Non-Application Layer Protocol)
💻

Malware Triage

  1. Hash lookup — MD5/SHA1/SHA256 against VirusTotal (or local intel). Detection ratio matters.
  2. Static indicators — File type, size, PE header anomalies, embedded strings (IPs, URLs, registry keys).
  3. Sandbox report — Behavioral indicators: dropped files, registry modifications, network connections, persistence mechanisms.
  4. Process tree — How did the sample execute? Office → wscript → powershell is a red flag chain.
  5. Persistence — Check Run keys, scheduled tasks, services, startup folder.
  6. Verdict — TP if AV detections or behavioral indicators present. Escalate all confirmed malware.
  7. Response — Isolate, preserve artifacts (memory dump), IOC extraction, sweep environment for same hash.
MITRE: T1059 (Scripting), T1547 (Autostart), T1055 (Process Injection), T1486 (Ransomware)
